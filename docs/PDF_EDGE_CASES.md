# PDF edge-case checks

`tests/pdf-robustness.test.mjs` checks the raster PDF modules without starting a
browser. Run it with `node --test tests/pdf-robustness.test.mjs`, or use `npm test`
for the complete unit suite. Assertions describe the intended contract; a failing
assertion remains an integration issue and must not be treated as accepted behavior.

These checks use PDF.js 6.4.299 and pdf-lib 1.17.1 from the local installation.
The writer under test imports the vendored pdf-lib used by the application.
Output inspection uses the installed pdf-lib parser and, for geometry and text
extraction, the installed PDF.js parser. Fixtures contain only invented data.

## Module checks

| Area | Checks | Scope of the evidence |
| --- | --- | --- |
| Page geometry | Negative crop origins, fractional crop dimensions, UserUnit 0.5/1/2, and all four quarter turns agree with the installed PDF.js viewport. | CropBox is inside MediaBox. This does not establish arbitrary malformed-box recovery or visual fidelity. |
| Placement | Decode the actual writer's content matrices, combine them with the output PDF.js viewport, and check all four image corners for every quarter turn. | Proves full-page coverage and corner orientation algebraically, including physical page dimensions. No viewer screenshot is compared. |
| Envelope | Classic xref tables, object streams, LF/CR/CRLF line endings, ordinary trailing whitespace, and nonzero page origins are accepted. | Fixtures are generated by pdf-lib or a minimal independent serializer. This is not a broad producer corpus. |
| Malformed envelope | Truncated EOF, appended non-PDF payload, unsupported version, invalid xref numbers, empty input and incorrect byte-container type are rejected. | An envelope check is a preflight, not a complete PDF parser. A valid-looking object at an xref offset does not prove a valid xref structure. |
| Mask data | Integer bounds, positive dimensions, edge-touching masks, invalid numeric/string inputs, the 200-mask boundary and copying are checked. | Additional contract assertions require sparse arrays to fail before rendering. |
| Snapshot | Mutating current-page and future-page masks after export starts does not change the embedded masks. | Covers the writer's snapshot. App replacement, review-state and download ownership require browser checks. |
| Pixels | Decode embedded RGB streams; check complete small mask rectangles, known outside pixels, and partially transparent pixels composited onto white. | Uses a small Canvas stand-in with explicit compositing and PNG encoding. No browser color-management or antialiasing claim follows. |
| Failure paths | Pre-abort, abort during delayed PNG encoding, failure on the last page, unavailable context, wrong raster dimensions, synchronous/null/wrong-type encoding, invalid PNG, embedding, flushing and serialization failures reject the export. | Owned canvases are resized to 1 x 1. Writer failures allow a subsequent fresh export. A render callback owns resources it allocates before rejecting. |
| Encoded budget | Reject a reported PNG size above 80,000,000 bytes before reading its buffer. | Synthetic size avoids allocating a large test buffer. No peak-memory bound is established. |
| Source boundary | Unrelated source-byte, text, metadata, attachment and action properties are never read by the writer. Output has a single image resource per checked page, no fonts, no catalog action/attachment/form/layer structures and no extractable text. | Checks the writer API with synthetic rasters, including pages with no masks. It does not prove that every input rendering feature is supported. |

The integrated writer disables pdf-lib's generated metadata. Both the boundary
check and independent export inspector require an absent output Info dictionary.

## Cancellation and cleanup contract

PDF.js documents that document cleanup must not run while rendering is ongoing
(`types/src/display/api.d.ts`, `PDFDocumentProxy.cleanup`). In the installed build,
`PDFPageProxy.cleanup()` can return false while an operator list is incomplete,
and document cleanup can reject. Render cancellation can defer operator-list
cleanup, so cancellation alone does not establish that document cleanup is ready.

The test evaluates the application's unchanged `LocalPdf` class body with
a fake PDF.js document. The fake can reject cleanup immediately after cancelling
a render. The intended assertions require an `AbortError`, released pixels, and a
successful subsequent render. This test seam exercises application ordering; it
does not reproduce a real worker's scheduling or prove a browser recovery path.
The class-source anchor is explicit and must be updated if the class is refactored.

## Remaining acceptance work

Local font and packed CMap bytes are cached for each open PDF, with limits of
4,000,000 bytes per resource, 16,000,000 bytes total and 256 resources. Document
cleanup retains this public resource cache; replacement or disposal clears it
and aborts pending fetches. A required-resource fetch failure prevents preview
and export instead of accepting PDF.js fallback rendering. This does not cache
source bytes, text or page images. Unit checks cover resource failures, budgets,
buffer transfer, disposal and swallowed renderer errors. Attended checks must
compare every output RGB pixel before and after warmed offline export and verify
missing fonts and CMaps fail closed in the real worker.

- Run the application with its actual browser PDF.js build and worker, effective
  CSP, local font/CMap/decoder resources, and real Canvas PNG encoding. Node parsing
  uses the legacy build for its Node polyfills; optional native-canvas warnings are
  expected because no rendering is requested.
- Independently render exported PDFs and compare every page's appearance, crop,
  small text, corner masks, transparent edges and known unmasked regions. Include
  CropBox/MediaBox intersections, inherited boxes/rotation, extreme UserUnit and
  fractional dimensions close to pixel-rounding boundaries.
- Test encryption including empty passwords, forms/signatures/XFA, optional
  content, annotations without usable appearances, malformed page trees, damaged
  streams, leading junk and unusual trailers. Strict envelope rejection is separate
  from whether PDF.js could repair a file. This suite does not justify relaxing it.
- Exercise real file replacement, overlapping navigation, cancellation before and
  after rendering, page teardown, late errors, save cancellation and stale download
  guards. Encoding cancellation is checked even when a callback never fires.
- Measure memory and responsiveness on target devices. At the configured maximum,
  one 16-million-pixel RGBA raster alone is about 64 MB. PDF.js source-image decoding,
  PNG encoding/decoding and writer serialization add buffers. Input bytes and page
  pixel counts do not bound decoded source-image memory.

The installed pdf-lib `PDFImage.embed()` clears its embedder after flushing, making
decoded PNG buffers eligible for collection. Compressed image streams remain in
the document until serialization, and garbage collection timing is unspecified.
The final 128,000,000-byte output check occurs after `save()` allocates its result.
Neither sequential rendering nor these limits establish safe memory use on a
particular device. Keep the fixed 150 DPI and reject over-budget work rather than
silently lowering resolution or omitting pages.

See [the acceptance plan](PDF_ACCEPTANCE.md) for broader visual, privacy, browser,
accessibility and image-regression checks. Passing module tests alone do not
establish release readiness.
